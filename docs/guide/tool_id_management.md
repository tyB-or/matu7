# 工具ID与配置管理

本文档详细描述Matu7系统中的工具ID生成、配置保存和恢复机制，特别是针对工具移动、重命名和删除场景的处理逻辑。

## 工具ID机制

### ID格式与生成

- **ID格式**: `{工具名称}-{YYYYMMDD}`，例如`nmap-20250720`
- **ID文件**: 每个工具目录中会创建一个隐藏的ID文件，格式为`.{工具ID}.json`
- **ID唯一性**: ID用于唯一标识工具，即使工具被移动或重命名，只要ID文件存在，系统仍能识别它是同一个工具

### ID文件处理

- **新工具扫描**: 首次扫描到工具时，系统会生成ID并创建ID文件
- **旧格式兼容**: 系统会自动将旧格式的`.id.json`文件转换为新格式`.{工具ID}.json`
- **ID文件检测**: 扫描工具时会检查目录中是否存在ID文件，并从中提取ID

## 工具配置管理

### 配置存储

- **配置文件**: 所有工具配置存储在`config/offline_tools_*.json`文件中
- **删除工具配置**: 已删除工具的配置存储在`config/offline_tool_delete.json`中
- **笔记文件**: 工具笔记存储在`notes/offline_tools/{工具ID}.txt`中

### 工具移动与重命名

当工具被移动或重命名时，系统会执行以下操作：

1. **检测变更**: 系统通过比较新旧工具列表，检测工具的移动或重命名
2. **保存配置**: 将原始工具配置保存到删除工具配置文件中
3. **恢复配置**: 在新位置检测到带有ID文件的工具时，系统会：
   - 从删除工具配置中查找匹配的ID
   - 恢复原始配置，但只更新路径和分类信息，保留原始名称和其他所有配置
   - 从删除工具配置中移除该条目

### 工具删除

当工具被真正删除时（文件系统中不再存在）：

1. **检测删除**: 系统检测到工具ID和路径都不存在于新扫描结果中
2. **保存配置**: 将完整配置保存到删除工具配置文件中，以便将来可能的恢复

## 工具恢复机制

当检测到新增工具时，系统会尝试恢复其配置：

1. **ID匹配**: 首先通过ID精确匹配查找已删除的配置
2. **目录名匹配**: 如果ID匹配失败，则尝试通过工具目录名匹配
3. **ID前缀匹配**: 如果上述都失败，则尝试通过ID的前缀部分（工具名部分）匹配
4. **配置恢复**: 找到匹配的已删除配置后，恢复所有原始配置，只更新路径和分类信息
5. **移除记录**: 成功恢复后，从已删除配置中移除该记录

## 刷新工具逻辑

点击"刷新工具"按钮时，系统执行以下操作：

1. **扫描工具库**: 扫描当前配置的工具库路径，获取所有工具信息
2. **对比工具列表**: 将扫描结果与当前配置中的工具列表进行对比
3. **处理删除工具**: 检测并处理已删除、移动或重命名的工具
4. **处理新增工具**: 检测新增工具，尝试从已删除配置中恢复配置
5. **保留配置信息**: 对于路径变更但ID保持不变的工具，保留所有原始配置
6. **更新配置文件**: 将更新后的工具列表保存到配置文件中

## 注意事项

- **ID文件重要性**: ID文件是识别工具身份的关键，请勿手动删除或修改
- **工具移动**: 移动工具时，请保留其ID文件，以确保配置能被正确恢复
- **配置备份**: 系统会自动备份已删除工具的配置，无需手动操作
- **恢复优先级**: 系统优先通过ID匹配恢复配置，其次是目录名和ID前缀匹配
